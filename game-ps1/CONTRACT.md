# 《近视眼勇闯恐怖游戏 · PS1》构建契约

知乎黑客松 2026「看山任意门」3D 番外篇：把盐言故事《近视眼勇闯恐怖游戏》
（作者：沈南因）做成一个 **PS1 复古画风的网页 3D 小游戏**。
纯静态站点（Vite + TypeScript + Three.js），产物 `dist/` 可直接丢 Cloudflare Pages / Vercel。
**零外部素材**：所有几何体程序化生成，所有音效 WebAudio 合成。

> 本文件是唯一对接标准。类型定义在 `src/engine/contract.ts`（只读，不改）。
> 每个 agent 只写自己名下的文件（见文末「文件所有权」），占位实现可整体覆盖。

## 1. 故事梗概（素材边界）

女主车祸死亡，被拉进恐怖副本「幸福之家」：一栋 30 层大楼，一梯一户，每层住一名玩家，
屋里住着扮演玩家亲人的诡异。女主因高度近视而看不清远处的人与轮廓，仍选择把眼前的小孩当作需要照料的家人。

原文只到 113 行（来人回家、挥开思思、女主起身斥责处截断）。所谓“完整剧情”只指**从原文 11 行播报到 113 行断句的完整首章**。不编造后续：
游戏止于女主已经起身斥责后的立场选择；三种章末卡只记录玩家自己的语气与站位，不断定思思伤势、来人反应、家庭关系或七日结局。

## 2. 核心体验

- **近视即渲染**：约 1 米内仍有贴脸可辨的清晰度；越过这一焦距，PS1 低清、雾与低模轮廓便迅速吞掉细节，约 2–3 米外只剩轮廓——画风就是设定。建筑不能因镜头移动而扭动或游纹。
- **眯眼（squint）**：按住右键/Q，远处变清晰；但看清恐怖真身会涨**惊悚值**。
  玩家自己权衡「看清世界」还是「保持幸福」。
- **惊悚值 0–100**：场景事件涨跌；到 100 当场死亡（bad ending）。
- **家常用恐怖原料**：给女儿换血裙→白裙、擦脸、哄午睡、拖地铲墙——温情动作配阴森环境，反差即趣味。

## 3. 任务链（gameplay 状态机，约 10–15 分钟）

| # | 阶段 | 内容 | 惊悚值 |
|---|------|------|--------|
| 0 | 楼前入场、问规则与选层 | 黑屏播报 → 白光后的近视感知，主角站在**大楼外**；走近红姐、俊哥问清死亡、积分、惊悚值与一梯一户规则 → 低楼层被先到者选走，主角因没跟上人群被送往 30 层 → 在 30F 走廊从冷意/血腥气、近处红墙与昏光辨认环境 → 走到自家门口，用回家的口吻拍门 | 0 |
| 1 | 门口初见 | 门**向屋内**打开、凉气；思思从门内约 2.65m 处以无五官红裙/双辫剪影停留，随后穿过门槛扑入走廊掐脖。门口一拍后她以地面侧跟方式随玩家入屋，不会贴在镜头正前方或改变模型尺度。 | +5 门开；+10 被掐 |
| 2 | 照料链 | 连续交互：白裙 → 换衣 → 热毛巾 → 擦脸 → 索吻/「谢谢妈妈」 → 哄午睡。玩家在来人开口前只看见“小孩”，不知道她叫思思。 | −10 被亲 |
| 3 | 播报与群消息 | `sys` 播报 30→20；沙发手机必须贴近（相机距手机 <0.6m）才可读。群聊覆盖三楼、十楼和惊悚值的**转述**，是主线必经信息而非可跳过支线。 | +5 读消息 |
| 4 | 家务 | 浴室拿拖把 → 客厅拖地 3 段（红→白）→ 两块凝固墙渍各铲 3 次。 | 0 |
| 5 | 午睡与惊醒 | 沙发交互睡觉 → 画面渐黑 → 醒来房子暗沉，`ps1.setMyopia` 日常模糊加重。 | +10 |
| 6 | 来人、思思与撞击 | 来人先叫出“思思” → 思思维护主角但保留“留着好好玩”的复杂性 → 来人不回应、挥开思思 → NPC 真正撞到阳台玻璃时才播放碎裂/撞击并生成碎片。 | +20 |
| 7 | 截断点与立场 | 来人在撞击后否认父女称呼；主角必然先起身斥责，再选维护/缓和/暂退。`boss.confront` 进入压迫演出。 | 维护+10 / 缓和+5 / 暂退+15 |
| 8 | 首章记录 | `end()` 展示玩家自己的立场记录；不添加任何角色回应或原文第 113 行后的结果。 | — |

交互全部走 `Interactable`（position/radius/prompt/available/onInteract）；gameplay 用
`available` 做顺序门控（如未拿白裙时「换衣服」不可见）。

## 4. 眯眼与惊悚值规则

- 常态：近视模糊 ≈ `setMyopia(0.35)`（1 米内不额外失焦；其外快速进入雾化，2–3 米外只剩轮廓）。
- 按住眯眼：`setMyopia(0)`（清晰）＋ 视野收窄暗角；松手回 0.35。
- **恐怖凝视**：眯眼时若视野中心 10° 内出现「真身目标」（来人、血裙形态的小孩、
  wallStain 特写），惊悚值 +3/秒；同时给 HUD 红脉冲提示。眯眼只改变互动版的风险，不提供原文没有给出的剧情答案。
  gameplay 用每帧 `update(dt)` 检测（目标点位由 npc/world 锚点提供）。
- 惊悚值 HUD：右上复古条，>70 红色脉冲 + 心跳加速（`audio.setFear`）。

## 7. NPC 状态表（npc agent 实现；gameplay 只调 `setState`）

**思思 `sisi`**（萝莉鬼，双辫，红裙/白裙两套材质 + 干净脸切换）：
`lunge`（从门内扑入 30F 走廊掐脖）→ `held`（门口后在玩家身侧地面随行，可进入屋内）→ `changed`（白裙）→ `clean`（擦净脸）→
`nap`（床上躺好）→ `defend`（对峙时挡在女主前）→ `thrown`（撞向阳台玻璃，骨骼散架感）

**大 Boss `boss`**（高瘦黑影，常态无面；清晰视野下可见真身细节——断头缝线、过长手臂）：
`hidden` → `arrive`（玄关现身，压迫感步态）→ `confront`（对峙）

NPC 程序化动画即可（关键帧插值/正弦摆动），不引外部模型。

## 8. PS1 画风规格（engine renderer 必须实现）

1. 内部低分辨率渲染（320×240 渲染目标），nearest-neighbor 放大到全屏，`image-rendering: pixelated`。
2. 建筑几何和 UV 必须透视稳定：禁止逐帧或随镜头的顶点吸附、仿放射 UV 游动。
3. 墙皮近处点采样，远处/斜视使用 mip 级别过滤，防止重复小纹理在移动中爬行。
4. 浓雾 + 暗色调色板（暗红/冷灰/霉绿），可选 Bayer 抖动色带。
5. 全屏合成：眯眼暗角（vignette）＋ 轻微色散；`flashWhite` / `shake` 供剧情调用。
6. 目标 60fps（M 系 Mac），但也别过度堆多边形——整屋 < 30k 三角面。

## 9. 主循环职责划分

- **engine（main.ts + engine/\*）**：渲染器/PS1 管线/相机；指针锁定第一人称
  （WASD+鼠标，撞 AABB 滑动碰撞，眼高 1.6m）；每帧调 `game.update(dt)` 后 `input.consume()`。
  触屏：左半屏虚拟摇杆移动、右半屏拖动视角、中央点按=交互、双指按住=眯眼（尽力而为）。
- **world**：`buildWorld(scene)` → `WorldData`；大楼外、30F 走廊、墙体/家具的碰撞盒；锚点；灯光
  （楼前与走廊冷雾，玄关冷光、客厅暖黄台灯+月光冷蓝、浴室惨白、公主房粉暗）。
- **npc**：`createNPCs(scene)` → `{ sisi, boss }`；各自 update/setState 动画。
- **gameplay（game.ts + fear.ts + hud.ts + interact.ts）**：§3 状态机、§4 眯眼惊悚规则、
  DOM HUD（惊悚值条/字幕/系统横幅/选项框/结局页，复古衬线/像素字体风）、交互检测
  （每帧对 interactables 找最近可用项 → 显示 prompt → input.interactPressed 触发）。

## 10. 验收标准（每个 agent 的自测门槛）

- `npm install && npm run build` 通过（TS strict 零错）。
- engine：空白场景能看到 PS1 效果（低清像素、雾、稳定建筑），按 WASD 相机动、指针锁定正常。
- world：锚点齐全、碰撞盒约束楼前/30F 走廊/屋内可走范围、灯光氛围对。
- npc：两个 NPC setState 各状态动画正确、无 T-pose 穿帮。
- gameplay：§3 八阶段可按 E 走完；须覆盖入场/选层/群消息/照料/家务/午睡/撞击/截断点；三张首章记录与 `dead` 可达，且不输出原文未给出的角色回应或通关结果。
- 集成后：ego-browser 打开 dev server 能玩通楼前问规则→30F 走廊观察→拍门→初见→换裙→擦脸→午睡。
