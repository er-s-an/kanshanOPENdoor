## 门厅集成与发布（2026-09-15）

- **统一构建命令**：从 `../game/` 执行 `npm run build:experiences`。它先构建门厅，
  再构建本项目，并把 `game-ps1/dist/` 复制到最终发布目录
  `game/dist/myopia-3d/`。不要只上传本项目的 `dist/`，否则会绕过任意门。
- **正式入口**：近视眼是 `/myopia-3d/`，端妃是
  `/myopia-3d/end-consort.html`；门户的两张 3D 门卡会经过原有开门转场再进入对应页。
  门厅根路径用 `?story=myopia-3d` 或 `?story=consort-3d` 可定位并高亮对应门。
- **回门/分享**：两页都可回任意门；记录卡 QR 与系统分享只带上述世界 ID，绝不带
  存档、进度、恐惧值或玩家分支。作为门户子目录部署时会保留部署子路径；单独预览时
  回退到既定线上门户。
- **开发态**：先在本项目运行 `npm run build`，再在 `../game/` 运行 `npm run dev`；
  Vite 会把本项目 `dist/` 只读挂到 `http://localhost:5173/myopia-3d/`，无须每次改动
  都重建门厅。缺少 3D 产物会返回明确的构建提示。
- **生产态**：构建后在 `../game/` 运行 `npm start` 可由同一 Node 网关托管门户与两页
  3D 静态文件。纯静态平台应发布 `../game/dist/` 并保留目录索引及相对 assets；门户
  的 `/api` 仍须有独立的网关/服务端适配，密钥不得进静态产物。

## 关键裁决（改代码前必读）

1. **完整 = 完整开放首章**，不是续写小说；原文 113 行之后不得给角色、关系、伤势或七日结果下结论。
2. **三张首章记录**只记录维护/缓和/暂退的玩家自身动作；不再使用 truth/haze/peep 等虚构性结局。
3. 手机阅读是**必做主线**；必须物理靠近 `<0.6m`，读到的是来源明确的玩家群转述。
4. **开场必须在门外**：大楼外问规则与选层、30F 走廊观察和走到家门拍门均为可玩前置；门向屋内开，思思从门内扑入走廊，抱住后才进屋。

## 已知坑（前代理实测）

- 不要重新引入 `noperspective`、`(uv·w,w)` 仿放射映射或 clip-space vertex snapping；它们会让墙面在移动时游动/跳格。
- 5173 端口常被本机其他项目占用；dev 自检用 5373 成功过。
- `squintOn/Off` 音效引擎在输入边沿自播，gameplay 只调 `ps1.setMyopia`（语义：0=眯眼清晰，0.35=日常，0.55=惊醒后，1=全盲）。
- world 材质全 `MeshLambertMaterial`，由 renderer 统一设置近处像素、墙皮远处 mip 采样；别换 ShaderMaterial 全替换。
- `setMyopia` 旧注释（0=日常）已修正为 §4 语义。
- headless Chromium 下指针锁定不可用（环境问题），真浏览器验证才行。
