## 2. Hidden coupling / global state / lifecycle leaks / fixed-template assumptions

**Blockers for a free SceneModule architecture, in severity order:**

1. **No teardown anywhere in the engine layer.** `PS1Pipeline` (renderer.ts:115-169), `FPSInput` (input.ts:120-133, 138-154, 257-283), and `SynthAudio` (audio.ts) have no `dispose()`. Window/document/canvas listeners survive any host unload; the audio context never closes; the 320×240 RT + depth texture + composite material are never freed. Only `WorldAssembler.dispose` (world-assembler.ts:106-111), `RuntimeHUD.destroy` (hud.ts:154-157), blue-blood's `loadWorld` (main.ts:127-136), and glass-fragment expiry (game.ts:1026-1027) dispose anything. A host that loads/unloads SceneModules will leak GPU + listeners per module.

2. **Four RAF loops, four hosts, no shared clock, no fixed step.** Every host clamps variable dt to 0.05 (main.ts:346, player.ts:117, blue-blood main.ts:582, end-consort main.ts:813) and passes raw dt to simulation. There is no accumulator or fixed-step simulation clock anywhere — the target's "fixed-step simulation clock" is entirely missing. Loop-order convention exists only as a comment (main.ts:4, main.ts:395-400).

3. **Squint is a five-way hard-coded coupling for one verb.** Input decides it (right-mouse/KeyQ/touch: input.ts:88,143,169) → main loop plays edge audio + slows movement 25% (main.ts:361, 388-393) → pipeline narrows the vignette (renderer.ts:193-195, 93-97) → Game resets myopia to 0 when squinting, i.e. squint=see-clear is the horror mechanic (game.ts:145-146) → fear gaze check only fires while squinting (game.ts:148-154, fear.ts:54-67). Nothing is data; you cannot redefine or remove "squint" without touching all five sites.

4. **The renderer is preset-coupled to horror.** Fog density is recomputed from myopia every frame (renderer.ts:242-244) against `FOG_BASE/GAIN/POWER` constants (:18-20) with the dark-red `PS1_BG` (:14). The two later stories opt out by `setMyopia(0); setSquint(0)` (blue-blood main.ts:95, end-consort main.ts:84-85) **and** by swapping `scene.fog` from `FogExp2` to linear `Fog` — which silently disables the coupling because of the `instanceof FogExp2` check (renderer.ts:242). So "preset switch" today = an invisible type-check side effect, not a real preset abstraction.

5. **Four divergent collision implementations.** main.ts: per-axis AABB slide with player-radius expansion and y-band filter [0.35, 1.6] (:144-156). player.ts: whole-position candidate test, radius 0.25, no y-band (:81-105). blue-blood: bounds-rect + AABB, y-band [0.2, 1.6], radius 0.22 (main.ts:535-538). end-consort: AABB, y-band [0.3, 1.8], radius 0.24 (main.ts:803-806). Same conceptual system, four behaviors — pick one.

6. **main.ts hard-wires story events into the engine host.** `openingFreeMove`/`openingMovement`/`openingRelocate` listeners (main.ts:116-141) make the engine know specific story beats; `movementEnabled` gating (:116, :354-355) is engine state driven by narrative. `STORY_TEST` dev handle (:24-25, :176-343) exposes `game`/`world`/`npcs` on `window.__kanshan`.

7. **Three divergent save idioms.** `SaveStore` (IndexedDB, digest-versioned, CAS — save-store.ts) vs blue-blood's bare localStorage `{version:1, chapter}` (main.ts:8, 109-112) vs end-consort's none. Same product, three persistence contracts.

8. **Fixed-template assumptions in the data-driven runtime.** `StoryScene.template` is `'room-v1' | 'courtyard-v1'` (types.ts:72), `PrefabName` is a 6-item union (types.ts:52), `WorldAssembler.addTemplate`/`createPrefab` are switch statements (world-assembler.ts:113-186). The runtime is data-driven only inside a closed template set — a free SceneModule cannot express a `streetPerimeter` scene.

9. **Global/module-level state.** `SaveStore.memory` static Map (save-store.ts:12); `kit.ts` `MAT`/`TEX` module singletons (:77-140) shared by all apartment-derived worlds and never disposed; end-consort's ~40 module-scope `let` globals (main.ts:59-181); blue-blood instantiates at module scope (`try { new BlueBlood() }`, main.ts:603); `input.ts` `TOUCH` flag computed at import time (:8-9); `FPSInput` appends touch UI to `document.body` globally (:172).

10. **Contract shaped by one game, and frozen.** `contract.ts:1-4` declares the file unmodifiable and encodes `fear`/`say`/`sys`/`prompt`/endings (:111-127). `GameAPI.update`/`start` (:107-110) assume a single global game object updated per frame, not a graph of modules. Also `PS1API` omits `setSquint` (used cross-layer at main.ts:388, player.ts:119).

11. **NPC interface takes the whole game.** `NPCController.update(dt, g: GameAPI)` (contract.ts:39-41) hands every NPC the entire game API; NPCs reach into `g.world.anchors` by string name (npcs.ts:32-43), an unenforced cross-module string contract.

# Capability inventory: studio/ + packages/story-contract/ + scripts/ + tests/

**Headline finding up front:** there are **two digest functions** in this repo and they disagree. `studio/src/util.mjs:9-12` hashes `JSON.stringify(value)` (insertion-order-dependent), while `packages/story-contract/src/canonical.ts:59-61` hashes `canonicalJson` (recursively sorted keys, rejects non-finite numbers). Studio's own `build()` stores the **canonical** digest (`studio/src/contract.mjs:23`, `studio/src/services.mjs:138`), but `preview()`, `validate()` reports, `recordReview()`, `exportRevision()` and the public-export review gate all compute the **non-canonical** digest of the same package object (`services.mjs:107,159,168,182,194,208`). ## 2. Hidden coupling, global state, lifecycle leaks, fixed-template assumptions

**Blocking issues for a free SceneModule architecture**

1. **Closed-world format everywhere.** The legacy StoryPackage is enforced at every layer: hard enum unions (`types.ts:97-105`), closed root with `additionalProperties: false` (`validate.ts:315-321`), scene template enum re-hardcoded in three places (`validate.ts:243`, `studio/src/contract.mjs:11,83`), prefab enum likewise (`validate.ts:217`, `contract.mjs:12,87`), P0 limits 1–2 scenes / ≤40 beats / ±20 coordinates (`contract.mjs:34,73-74`, `validate.ts:155,362,365`), fixed action catalog of 6 kinds (`contract.mjs:7`, `types.ts:167-173`), fixed option arities (`validate.ts:301-309`). `capabilities()` advertises these hardcoded bounds as engine capability (`services.mjs:61,64`). A free SceneModule system must replace enum-driven catalogs with registered-module catalogs — today there is no registry mechanism at all.
2. **Hardcoded demo story path.** `bookstall-opening` appears verbatim in export (`services.mjs:206`) and preview asset serving (`http.mjs:94`). Both would serve the wrong identity for any other project.
3. **PLAYER_DIST resolved from source-file location** (`services.mjs:10`, `http.mjs:8`) — breaks if studio is bundled/copied; also couples studio to `game-ps1/dist` existing on disk (gracefully degraded, but silently).
4. **Module-level side effect in cli.mjs** (`cli.mjs:38-44`): importing the CLI module runs `main(process.argv)`. Any future host that imports CLI commands executes them once at load.
5. **Global state & lifecycle leaks**
   - `activeJobs` Map (`services.mjs:50`) is process-global, never rehydrated; jobs orphaned by process exit stay `running`/`queued` forever (nothing marks `interrupted`).
   - Job execution via `queueMicrotask` with `.catch(() => {})` (`services.mjs:224`) — fire-and-forget; unhandled errors swallowed.
   - HTTP server: one `StudioServices` instance per server (`http.mjs:10`), token generated per instance — multiple servers on the same workspace share no session concept.
   - `WorkspaceStore` default root `.story-workspaces` relative to **CWD** (`store.mjs:6`) — cwd-dependent global.
   - No `close()`/dispose on any class; `startStudioServer` returns server but services hold no resources beyond file handles — OK, but no shutdown ordering exists for jobs.
6. **Read-modify-write races without CAS**: revision import head-move (`services.mjs:112-128`), build/validate mutating and re-saving revisions (`services.mjs:139-140,170`), review push + save (`services.mjs:183`), `updateJob` get+assign+put (`store.mjs:76-81`). Fine for a single-user localhost tool; fatal for a concurrent Studio.
7. **Export review gate compares digests computed by the wrong function** (`services.mjs:194`): it re-derives `digest(revision.package)` at export time rather than comparing against the canonical `revision.build.packageDigest` — currently self-consistent, but the moment any path stores canonical digests in reviews, every public export breaks.
8. **Fixed-template web UI + verifier**: the UI has no generate/cancel (`app.mjs:18-25`), and the verifier's action-catalog drift check (`verify-ps1-studio.mjs:244-255`) will FAIL the build if `ACTION_CATALOG` changes without a matching schema edit — a coupling trap during format evolution.
