## 0. 一句话

**把知乎盐言故事一键编译成「一个人也能玩的剧本杀」。**

玩家不是在读故事，而是穿越进故事当侦探：审讯 NPC、搜集线索、抓出矛盾、限时指认。
我们交的不是一个剧本杀，是一台**剧本杀生成器**——这是全部差异化的来源。

---

## 1. 产品定位

| 项 | 内容 |
|---|---|
| 产品名 | 看山任意门（Kanshan Portal） |
| 定位 | 盐言 IP 互动改编生成器；「单人剧本杀」是首个打透的编译目标 |
| 一句话 pitch | 把盐言故事变成一个人也能玩的剧本杀 |
| 对知乎的价值 | 盐言库存 → 互动序章 → 悬念最高点引流原文（盐言会员转化），反哺创作者 |

**为什么是"生成器"而不是"一个游戏"：**
盐言的变现链路目前是两层——会员订阅 + 短剧授权（2025 上半年近百部）。**互动改编是空白的第三层**，但手工改编一篇成本太高，只有生成器能让"库存互动化"的边际成本趋零。评委（知乎各业务线负责人）听得懂这个语言。

## 2. 背景与机会（评委视角）

- **盐言 × Vidu 今年 5 月办过 AI 漫剧黑客松**——官方在推 IP 改编，预期有撞题者。我们的差异不是"改编了一部作品"，而是"造了改编的机器"：demo 现场可以喂一篇新故事给管线。
- **S1 评委口味**（复盘结论）：反炫技、"拒绝宏大叙事"；冠军《人生样本库》赢在给存量内容创造新连接——对应我们的「作者反哺」叙事；刘看山 IP 受评委偏爱——刘看山在作品里是引路人 + 华生位。
- **剧本杀心智现成**：学生群体对剧本杀零解释成本；「单人剧本杀」有市场先例（解谜书、《谜宫》系列）。多人社交层用**异步比较海报**补回（你的推理 vs 其他侦探的结局分布），不做实时多人房。

---

## 3. 用户与场景

- **主要用户**：知乎盐言悬疑品类读者、剧本杀/推理爱好者、学生群体。
- **核心场景**：刷到一篇盐言 → 不只是读，而是"推门进去玩 10–15 分钟" → 在悬念最高点被勾回原文（会员转化点）。
- **创作者侧**：作者的故事获得互动改编形态，玩家被导回原文——反哺而非截取。

---

## 4. 核心玩法循环（单人剧本杀）

一局 10–15 分钟：

1. **推门**：刘看山引路，点题"穿越进故事"机制。
2. **入局**：novel 场景，第一人称经历案发（原著改写，保留关键描写与金句）。
3. **搜证三件套**：
   - **审讯突破**：与嫌疑人 NPC 自由对话，目标显性化（"让他说出昨晚在哪"），达成得线索；
   - **关键词取证**：自由输入关键词翻证物/档案（Her Story 式）；**卡壳 3 轮刘看山递提示**（混合方案，自由输入为主）；
   - **指证矛盾**：针对 NPC 的某句陈述出示正确线索 → 破防吐出新线索。**矛盾点在编译期写死，LLM 只润色、绝不发明证据。**
4. **限时指认**：关键选项带线索门槛——没搜到关键线索时，指认选项**灰显锁定**并提示"还缺证据"（`requires` 条件门）。
5. **复盘结算**：推理报告（线索 x/n、用时、判断对错）+ 稀有度结局海报（结局编号 + 稀有度 + 能力雷达，**不剧透**，Wordle 化可分享）。

### 两档文本处理（诚实框架，管线自动选档）

| 档位 | 文本条件 | 指认对象 | 收束方式 |
|---|---|---|---|
| A · 完整闭环 | 拿到完整故事 | 全书真凶 | 真相揭示 + 复盘评分 |
| B · 序章模式 | API 试读（~3000 字截断） | **本章内可解疑点**（从试读文本实际内容提取） | 推理进度报告 + "你怀疑谁"站队 + 引流原文卡 |
| B′ · 纯序章 | 试读且章内无可解疑点 | 无指认环节 | 搜证 + 站队 + 引流 |

- 管线在 analyze 阶段自动检测截断（文本断在剧情中段、无结局）→ 自动选档；
- **绝不编造真相**：analyze 已有"只抽取原文明确呈现的内容"红线，正好兼容截断文本；
- 9/13 10:00 API 全开后若放出完整章节，同一管线自动升 A 档，无需改代码。

## 5. 生成器：输入 → 输出

**输入**：一篇盐言 txt（官方 API 池）+ 题材标签。
**输出**：game.json「案件档案」——

- `scenes`：案发 → 搜证 hub → 指认 → 收束 的 spine 骨架；
- `npcs`：嫌疑人卡（六字段 + 防线/秘密）；
- **线索即变量**：`clue_*` 前缀约定，复用现有运行时变量系统，引擎据此渲染线索簿；
- `contradictions`：矛盾点（哪句陈述 × 哪条线索 × 破防反应）；
- `choices`：带 `requires` 条件门。

### 契约扩展（最小改动，向后兼容）

```ts
// types.ts 唯一新增字段
interface Choice {
  id: string; text: string; next: string;
  set?: Record<string, string>;
  requires?: Record<string, string>;  // 新增：条件门，如 { clue_knife: "found" }
}
```

Scene / NpcCard / LoreEntry 契约不变；既有 3 篇编译产物不受影响。

### 管线五步改造点

| 步骤 | 现状 | 改造 |
|---|---|---|
| ingest | 分段 + 元信息 | 不变 |
| analyze | 抽取人物/时间线/伏笔 | **+题材判定**；悬疑题材时 **+案件提取**（嫌疑人、秘密、章内矛盾候选、截断检测） |
| design | 通用互动蓝图 | **+剧本杀模板**（条件激活）：spine 骨架、搜证 hub、线索分配、requires 门位置 |
| compile | 逐场景文本 + NPC 卡 | +线索与矛盾文本润色；NPC 卡加"防线/秘密"层 |
| validate | 图检查三件套 | **+剧本杀专项**：requires 可满足性（门槛变量在上游可获得）、每条线索都有来源场景、指认场景可达 |

### LLM 权限边界（防造假，评委问答弹药）

- **LLM 负责**：理解故事、提取嫌疑人/线索/矛盾候选、写 NPC 声口、文本润色；
- **确定性代码负责**：矛盾判定、线索门控、图完整性、结局可达性；
- **红线**：LLM 不发明证据、不编造结局。玩家永远不会遇到"AI 现场瞎编的假线索"（Vaudeville 的前车之鉴）。

## 6. 题材路由（生成器的"盘活库存"叙事）

| 题材 | 模板 | 机制换皮（同一 `requires` 门） |
|---|---|---|
| 悬疑/推理/惊悚 | 剧本杀 | 搜证 → 指认真凶 |
| 情感 | 摊牌 | 心事=线索，摊牌=指认（"说出那句没说出口的话"需要足够了解 TA） |
| 无限流/玄幻 | 破局 | worldRules=死亡规则，找到生路=指认 |

48 小时内：**只打透悬疑模板**，另用 1 篇情感故事做换皮 demo 证明路由存在（《上岸》已编译，可改造）。

## 8. 引擎改造点（game/，按优先级）

1. `Choice.requires` 灰显 + 锁定提示（"还缺证据"）；
2. 线索簿 UI（`clue_*` 变量 → x/n 收集进度，常驻入口）；
3. chat 目标进度显性化（审讯突破的即时反馈）；
4. 复盘结算页 + 稀有度海报（分享图，人气奖弹药）；
5. 指认环节限次（软性压力，不做硬倒计时）。

## 9. 评审对齐（初审权重 → 打法）

| 维度 | 权重 | 我们的打法 |
|---|---|---|
| AI 场景价值 | 40% | 盐言引流转化 + 创作者反哺，业务价值直白可量化（悬念处引流原文） |
| 创新度 | 25% | 编译器路线无产品级对手；现场喂新故事是唯一不可抄袭的差异 |
| 完成度 | 25% | 确定性主干 + 受限即兴，demo 必跑；3 篇实证生成器 |

**路演 3 分钟脚本方向**：30s 痛点（盐言只能读）→ 90s 实玩《蓝血》指认时刻 → 30s 生成器证明（同一管线吐出第 2 篇）→ 30s 业务闭环（盐言第三层变现 + 创作者反哺）。

## 12. 开放问题（附建议，可推翻）

1. **搜证关键词：自由输入 vs 点选？** → 建议混合：自由输入为主（Her Story 的考古感），卡壳 3 轮刘看山递提示（防流失）。
2. **序章"站队"结局会不会显得残缺？** → 设计成"推理进度报告"：你搜集了 x/n 条线索、锁定了几号嫌疑人、你的判断与结局稀有度——把"没有真相"变成"去读原文验证你的推理"，截断即钩子。
3. **要不要真·多人？** → 不要。异步比较海报补社交层；多人房留 V2，路演 Q&A 可主动讲这个演进方向。
