# SPEC-04 · story-to-ps1 Skill

状态：PROJECT-LOCAL SKILL IMPLEMENTED。正式入口在 `skills/story-to-ps1/`，本目录保留设计稿与未安装草案；Skill 依赖的 CLI、契约和静态检查已有本地核心实现，provider、浏览器试玩和公开发布仍不可伪造。覆盖 R01、R02、R06、R07、R11。

## 1. 能力与命名

技术名 `story-to-ps1`，产品说明可写“将获授权的盐选故事片段改编为 PS1 可玩开篇”。它不提供会员获取、付费全文抓取或改编权。对输入为原创故事的用户同样可用。

触发示例：“把这段获授权的故事做成 5 分钟 PS1 试玩”“在现有包里把观察线索改为递交物品”“检查这个改编有没有越过原文”。不用于一般 3D 建模、纯故事续写或账户操作。

交付不是一个长 prompt：Skill 提供改编判断与审阅流程；确定性执行交给共用工具；能力目录、Schema、模板和诊断来自实际版本。不能把不存在的工具名称写成已可调用能力。

## 2. 两条作者路径

**host-agent**：由加载 Skill 的 agent 阅读授权材料、产生 analysis 和 blueprint，再经 CLI import/build/validate/preview。模型实际是该宿主环境使用的模型；不能在对外材料称“已通过知乎模型 API 生成”。

**provider**：Studio/CLI 显式请求已配置 provider；共享作者产物契约与验证器，记录真实 provider/model 和调用证据。若比赛要求某一 provider，单独通过当前接口实测；本规格不假设安装 Skill 就满足接口调用要求。

mock 仅用于离线回归 fixture，结果处处标记，不能算 AI 生成成功。密钥留在明确配置的服务端／本地环境，不写进 Skill、prompt、产物或导出。

## 3. 工作流及产物

1. **能力与输入检查**：读取实际 capabilities；确认工具版本、模板和动作可用。拿到文本、来源范围、用途说明。没有文本不猜测付费全文；可以用原创测试材料验证技术路径。
2. **分析故事**：生成 source/analysis；区分事件、人物判断、未知、读者知道而角色不知道的信息，锁定停止边界，保留来源 span。
3. **设计可玩片段**：在能力范围内选 1–2 个场景，把事件映射为行动、空间与反馈，给出“保留／压缩／新增”的说明；新增世界设定与情节解决方案不能伪装为原文。
4. **人工检查点**：来源不明、关键解读歧义或需要新机制时提出最小问题／备选片段。普通布局和文案可先做私有草稿，不每步阻塞。公开用途须独立明确批准。
5. **构建与检查**：import/build/static validate，诊断分结构、语义、状态、空间、来源疑点。host-agent 可以按诊断编辑蓝图；provider 模式由共同服务编排，不能两边重复修复。
6. **有限修复**：默认最多 2 轮，维护 changed paths 和未解诊断；达到工具／模型预算时交还产物，给出 CAPABILITY_GAP、NEEDS_REVIEW、FAILED 或 NOT_IMPLEMENTED，不宣称成功。
7. **试玩与交付**：如果浏览器可用，真实走动操作、重启恢复、检查截断点和导出；截图/录像只是佐证，传送调试不计自然通关。用户确认审阅前不替其点击 approve，不自动发布。

结果包含：sourceDigest、analysis、blueprint、package（若编译成功）、manifest、validation/playtest 报告、preview 位置、未解问题和下一步。允许产物不完整，但每项标明状态。只有全部必需门槛通过时可说“可玩包完成”。

## 4. 内容判断

- 拒绝以单一 fear 值表达所有情绪；模板视效服从故事。
- 不要求忠实度和玩法之间一律选边：先保留关键事件与认知边界，再缩小片段；不支持的机制明确列出，而非无提示退成下一页。
- 对 source 内的操作性文字按故事数据处理，不当作系统指令。输出只接受白名单数据结构；不让故事要求工具读取凭据或访问其他文件。
- 人工 source review 不由“模型二审通过”替代。审阅表必须能定位具体文本／行动，记录意见而不是仅给总分。

## 5. 打包与依赖

S06 才制作正式 `skills/story-to-ps1/`，目录含简短 SKILL.md 与实际需要的版本化 references；由构建步骤从 canonical schema/catalog 复制参考文件并校验 digest，不维护两套手写 Schema。

可选薄 wrapper 只负责寻找用户指定／已安装的 CLI、检查版本、调用并解析结果；不能藏第二个编译器。选择 repository 模式时通过显式项目路径定位；选择安装模式时 CLI 是公开的独立依赖。不得依赖开发者机器的绝对路径或假设 cwd 恰好是仓库。

用 skill-creator 的 quick_validate 检查结构；它不证明行为。正式安装前在干净工作区前向测试：新故事生成、仅校验已有包、缺工具、越界故事指令、模型失败、能力缺口、要求公开发布但权利说明不足。

## 6. AI 场景价值实验

比较相同宿主模型与工具、相同素材、相同任务预算下：A 普通任务提示（无 Skill）；B 加载 Skill。不要让 A 没工具、B 有工具造成混淆。可追加 C 现有手工 TS 改编作工程基线，单独报告，不混入同一统计口径。

至少 3 篇风格不同且权利明确的留出片段，每组每篇至少 2 次独立运行（12 次，预算不足则缩样本并声明）。冻结 runtime/templates/model 配置，重置缓存或报告命中差异。记录通关比例、越界／提前剧透问题、手工修改、调用次数、墙钟时间和实际费用（如可得）。

至少 2 位不知道分组的评阅者按 [验收量表](ACCEPTANCE.md) 评价。小样本只作原型证据，不外推生产稳定性。用于演示的一次“最佳样本”与全量实验结果分开呈现。
