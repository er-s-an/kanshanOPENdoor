# PRD · 故事改编工作台

状态：PROPOSED · P0 = 本轮计划的完整最小闭环，非当前实现。

## 1. 产品命题

面向故事创作者和运营：将获授权的故事片段，转换为 PS1 风格的可玩开篇，创作者可审阅来源、调整行动与空间、试玩、导出。玩家仍可回到原作；只有存在核验过的原作链接时才展示跳转入口。

对比赛的可展示叙述是“AI 把故事里的事件编排成玩家行动，并通过共同工具链检查和修复”，而不是“有很多生成按钮”。实际计分取决于届时有效规则和评委判断。

## 2. 角色与完整路径

创作者：提供片段与用途说明 → 审核故事事实、角色认知和截断点 → 选择场景方案 → 生成内容包 → 看报告／试玩 → 修改 → 批准指定版本 → 导出。

AI：提出分析和设计、生成结构化草稿、根据诊断修复；不能把推断改标成原文事实，不能自行批准发布，也不能生成任意脚本绕过能力限制。

运行时：确定地执行玩家输入和内容包；不调用模型裁决剧情真相或实时改变规则。

玩家：移动 → 靠近线索／人物 → 观察、取用、对话或选择 → 看见行为带来的变化 → 到达片段内的结尾／悬念边界 → 重玩或回到来源。

## 3. P0 范围

| 编号 | 需求 | 完成证据 |
| --- | --- | --- |
| R01 | 导入一个 UTF-8 故事片段及来源、用途、授权依据说明 | 来源摘要、哈希、引用范围；未知授权不允许标记公开可用 |
| R02 | 审阅事实、角色认知、关键事件、不可越过的片段边界 | 来源定位与新增内容标记，审批绑定输入和内容版本 |
| R03 | 从两个受控场景模板搭建空间 | 房间、庭院；对象位置、碰撞、交互可达性可检查 |
| R04 | 运行受控叙事动作 | inspect / collect / use / talk / choose / end；不执行包内 JS |
| R05 | 行动产生可见结果且存档可恢复 | 状态投影、一次性物品、事实揭示、确定性重放 |
| R06 | AI 编译并按诊断有限修复 | 明示模型模式、调用预算、尝试次数、失败报告 |
| R07 | Skill 可独立完成同一流程 | 在干净工作目录生成相同契约，工具缺失时明确停止 |
| R08 | Studio 可编辑并预览同一内容包 | 来源、剧情列表／属性表、试玩和诊断；刷新不丢已提交修订 |
| R09 | 输出可分享的静态游戏产物 | 不依赖创作者服务即可运行，无密钥／完整源稿／内部分析泄漏 |
| R10 | 同版引擎适配留出故事 | 不改运行时／模板代码，保存操作与修改记录 |
| R11 | 有可比较的 AI 场景价值证据 | 有无 Skill 的配对实验、时间与手工修改成本、盲评质量 |
| R12 | 保留现有作品与开发数据 | 原入口回归测试，独立存档命名空间，精确改动范围 |

每包上限：1 个输入片段（20,000 Unicode 码点以内）、1–2 个场景、每场景最多 32 个对象／32 个交互锚点、最多 40 个 beat、每 beat 最多 4 个选项。P0 仅有限布尔旗标、物品集合与已知事实集合；无任意数值公式或脚本。

单局 **5–10 分钟是设计目标，不是现有效果或硬性压缩要求**。首个技术样本可为 2–3 分钟；正式验收记录自然游玩时长及其分布，不为凑时长补写原文外剧情。

## 4. 不做什么

P0 不做：完整长篇自动改编、开放世界、自动生成任意 3D 模型、自由拖拽建模、联网多人、云端账户与协作、市场分发、运行时自由聊天、任意插件上传、自动发知乎、付费全文抓取。

P1：节点图、更多空间模板、有限谜题插件、移动端真机完善、更多故事回归、导入／导出体验。

P2：Ink 子集导入、受审插件 SDK、团队版本协作和经授权的发布渠道。P2 不是完成 P0 的前置条件。

## 5. 游戏性约束

- 悬疑故事可以用有限信息和观察；温暖故事可以用整理、递物、照料。PS1 是视觉风格，不等于所有故事都应有恐惧值、血色滤镜或追逐。
- 至少两项推进来自空间中的行动，且至少一项行动改变世界／背包／信息状态；单纯“继续阅读”不能通过可玩性验收。
- 为每个行动记录：原文事件 → 玩家目标 → 场景对象 → 操作 → 可见反馈 → 新的信息。无法映射时缩小改编片段，或明确提出超出当前引擎能力。
- 角色真名、阵营、真相不能在模型标签、日志、辅助文本、对白署名中提前揭示。包可被技术用户查看，承诺的是正常游玩不剧透，不是加密保密。

## 6. 成功与 Go/No-Go

G1：迁移一段现有作品 + 新运行时自然通关，旧作品仍可运行。

G2：冻结 runtime/template/schema 版本后，另一作者／执行环境通过 Skill 生成留出故事，无核心代码改动，来源审阅通过，可自然通关。

G3：同一包可在 Studio 修改、重新校验、审批、导出；导出包离开作者工作台仍可运行。

没有 G2，不对外称“通用故事转游戏”；仅有 G1，称“可复用运行时原型”。没有质量／成本对比，不宣称节省百分比或提高改编质量。具体测试见 [验收](ACCEPTANCE.md)。

## 7. 资源与里程碑估计

假设一名熟悉 TS/Three.js 的工程师，复用当前素材，使用已有模型访问方式，不包含账户平台／自由编辑器：

- 最早技术验证：约 3–5 个工程日，完成一个数据驱动的短片段，不代表完整产品。
- 完整 P0：约 12–20 个工程日，含受控场景、工具、Skill、轻量 Studio 和回归；多人并行不能简单除人数。
- 在 S03 迁移样本后重新估时；空间编辑、浏览器输入、模型稳定性是主要不确定项。若时间紧，先完成命令行 + Skill + 可分享样本，再做 Studio 编辑体验。

这些是工作量假设，不是现有任务进度、交付日期或比赛有效工期。
